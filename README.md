# OA阅答 v1.0.1

OA阅答是一款在 Windows 本机运行的中国专利审查意见辅助工作台。上传原申请文件、审查意见通知书和对比文件后，可以借助自己的 NotebookLM 账号形成争点清单、核对证据、逐项分析答复策略，并保存分析结果。

**普通用户请下载 [v1.0.1 发布包](https://github.com/talenlin/oa-response-drafter/releases/tag/v1.0.1)，无需下载源码或安装 Python。**

> 生成内容用于策略讨论和证据复核。正式提交前，请由专业人员核对原文、引证、修改依据及程序要求。

## 一、下载与启动

适用环境：**Windows 64 位**，电脑上安装 Chrome 或 Edge，并能正常访问自己的 Google / NotebookLM 账号。材料解析在本机进行，NotebookLM 登录、上传和分析需要联网。

在 [Releases](https://github.com/talenlin/oa-response-drafter/releases) 中选择 v1.0.1：

| 文件 | 使用方法 |
| --- | --- |
| `OA-Yueda-v1.0.1-lightweight-portable.zip` | 完整解压到一个文件夹，再双击其中的 `OA阅答.exe`。不要直接在压缩包内运行，也不要只复制 EXE。 |
| `OA-Yueda-v1.0.1-lightweight-setup.exe` | 双击后按提示安装，通过桌面或开始菜单快捷方式启动。 |

启动后会自动打开工作台，地址为 **http://127.0.0.1:8787/**。看到左下角“本地桥接器 运行中”，即可开始使用。程序运行期间也可手动打开这个地址。

轻量版附带 Python 运行环境和 office_oxide 文档转换组件，不包含 LibreOffice。首次处理 PDF 或扫描件时，还需在工作台完成 OCR 初始化。

## 二、首次连接 NotebookLM

1. 点击工作台右上角 **“连接 NotebookLM”**。
2. 在说明窗口中点击 **“在本机打开 Google 登录”**。
3. 在打开的 Chrome / Edge 窗口中，用自己的 Google 账号完成登录及必要验证。
4. 等待 OA阅答显示 **“已连接”**。浏览器登录成功后，工作台仍需要完成连接校验。

程序使用独立浏览器资料目录，后续通常会复用本机会话。若显示登录已失效，再次点击“连接 NotebookLM”重新登录。Google 密码由用户直接输入 Google 登录页。

## 三、一次完整使用流程

```mermaid
flowchart LR
    A[连接 NotebookLM] --> B[上传案件材料]
    B --> C[文本质量检查 / OCR]
    C --> D[确认账号与上传清单]
    D --> E[形成争点清单]
    E --> F[选择争点并分析]
    F --> G[核对证据 / 继续追问]
    G --> H[保存 DOCX / 归档]
```

### 1. 按类型上传材料

将文件拖入相应材料框，或点击选择文件：

| 材料类型 | 内容 | 是否必需 |
| --- | --- | --- |
| 原申请文件 | 说明书、权利要求书、附图，或包含上述材料的合并文件 | 必需 |
| 审查意见通知书 | 本轮 OA、审查意见或审查报告 | 必需 |
| 对比文件 | OA 引用的专利、论文等现有技术 | 按案件需要补充 |
| 已有意见陈述书 | 本轮答复草稿，或之前轮次的答复材料 | 可选 |

支持 PDF、DOC、DOCX 和文本材料。尽量使用清晰原件，文件名注明材料类型和轮次，避免混入其他案件的文件。

上传“已有意见陈述书”时，请核对 **“本文件用途”**：

- **优化本轮已有意见陈述书**：以草稿为基线，提出补充、修改、替换及权利要求调整建议。
- **作为此前答复背景材料**：作为历史答复背景使用。

### 2. 检查文本，必要时运行 OCR

1. 点击 **“启动文本质量检查”**，查看材料解析状态和预览。
2. 对需要 OCR 的材料，先点击 **“安装 / 初始化 OCR”**，完成首次环境和模型下载，再点击 **“启动 OCR 复核”**。
3. 等待所需材料处理完成，核对识别结果后继续。

OCR 首次初始化需要下载额外组件，可能耗时较长；后续会复用本机环境。请重点核对申请号、段落号、公式、附图标记、表格和扫描不清的内容。

旧 `.doc` 会在本机转成 `.docx`，顺序为 **本机 Microsoft Word → 随包 office_oxide 0.1.15 → 可用的 LibreOffice**。轻量版本身不携带 LibreOffice。复杂排版、文本框、公式或修订内容请对照原件检查。

### 3. 确认账号和上传清单

在发送确认窗口中核对当前 NotebookLM 账号、案件、轮次及实际上传文件，确认后提交。

每份材料只准备一个实际上传来源：可直接读取的 DOCX / PDF 使用原文件；旧 DOC 使用转换后的 DOCX；需要 OCR 的扫描材料使用识别后的 Markdown 文本。同一材料不会同时重复提交原件和文字副本。实际提交文件会在本地 `notebook-upload` 目录留存，便于核查。

### 4. 选择争点，逐项分析

1. 等待材料上传、NotebookLM 处理完成并形成争点清单。
2. 在 **“选择要分析的问题”** 中勾选争点，点击 **“分析已选争点”**。
3. 查看证据预览、引用片段和分析结果，回到原申请文件、OA 及对比文件核对。
4. 如需补充，在 **“继续追问”** 中输入围绕该争点的问题并提交。

每次问题尽量集中于一个争点，例如区别特征、技术问题、组合动机或某段答辩的修改，便于检查证据与论证是否对应。

### 5. 保存与归档

- 在分析结果中点击 **“保存为 DOCX”**，保存当前结果；也可以收藏回答。
- 点击 **“归档当前案件”**，在本机保留案件及答复记录。
- 点击 **“新建 OA 案件”**，按确认提示保留现有记录并进入新案件。
- 左侧 **“案件”** 页面用于查看本机案件，**“审计”** 页面用于查看相关操作记录。

## 四、上传较慢时，应该等多久？

材料上传到 NotebookLM 的速度取决于上行带宽、网络连接和文件大小。**上行速度只有约 100–200 KB/s 时，等待几十秒到几分钟很常见。**

| 文件大小 | 仅传输的估算时间 |
| --- | --- |
| 5 MB | 约 25–50 秒 |
| 10 MB | 约 50–100 秒 |
| 20 MB | 约 100–200 秒 |

以上按近似十进制计算，不含建立连接、服务端解析、OCR 和生成回答的时间。多份文件需要累计等待；“上传中”“处理中”和“正在分析”对应不同阶段。

- 保持程序、浏览器和网络连接，观察文件数量与任务状态，不要连续重复点击提交。
- 暂停其他大文件上传，优先使用可直接读取的清晰文件；不要将扫描件压缩到无法辨认。
- 若明确显示失败，先处理网络或登录问题，再通过界面重试。程序会尝试保留成功上传的来源并核对中断状态；不要手动删除 NotebookLM 来源来重置进度。
- 若长时间无变化且没有失败提示，记录任务状态和文件大小，再检查网络；不要仅因等待较长就判定任务失败。

## 五、数据保存与分享

安装版和免安装版默认将应用状态保存在当前 Windows 用户的：

```text
%LOCALAPPDATA%\OA阅答
```

在左侧 **“设置 → 本地存档位置”** 中可选择后续案件的存档文件夹。修改此设置只影响后续保存，已有存档不会自动移动。

登录资料保存在 OA阅答自己的本机目录中；旧工具用户首次运行时可能自动迁移旧工具导出的会话缓存。不要将应用数据目录、浏览器资料、Cookie、案件文件或运行日志打包后发给他人。

本仓库只提供脱敏源码和合成测试材料，发布包不附带作者的账号、案件或登录缓存。材料仅在用户确认后发送到其 NotebookLM 账号；NotebookLM 的可用性和数据处理以 Google 服务及账号设置为准。

关闭网页不会删除本地数据，也不一定停止服务。需要完全退出时，可在任务管理器中结束 OA阅答 对应的进程组，避免结束其他软件的 Python 进程。

## 六、常见问题

| 现象 | 处理方法 |
| --- | --- |
| 双击后页面打不开 | 确认 ZIP 已完整解压且文件齐全；启动后尝试打开 `http://127.0.0.1:8787/`，检查本机服务是否仍在运行。 |
| 浏览器已登录，工作台仍未连接 | 等待本机校验完成；若显示失败或过期，重新点击“连接 NotebookLM”，按工作台状态完成流程。 |
| DOC 转换失败 | 检查原文件是否损坏、加密或实际上不是 DOC；可在 Word / WPS 中另存为 DOCX 后重新上传。 |
| OCR 首次初始化慢或失败 | 检查组件下载网络，等待明确结果；失败后按提示重试。PDF / 扫描件需要额外 OCR 环境。 |
| 上传很慢 | 参照上一节估算，等待传输和后续解析；不要连续重复提交。 |
| 分析中途登录失效 | 重新连接 NotebookLM 后通过界面重试，保留本地材料和历史回答。 |
| 改存档位置后，旧案件没有一起移动 | 这是当前行为；原目录仍保留旧存档，请自行备份，勿直接删除。 |
| 引证、段落号或论证不准确 | 回到原文复核，针对争点继续追问或人工修改，不直接作为提交文本使用。 |

## 七、源码运行与开发

普通用户使用 Releases 中的安装版或免安装版即可。开发环境采用 Windows 64 位、Python 3.12；前端为静态 HTML / JavaScript，无需安装 Node.js 依赖。

```powershell
git clone https://github.com/talenlin/oa-response-drafter.git
cd oa-response-drafter
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe bridge\bridge.py
```

随后打开 <http://127.0.0.1:8787/>。源码运行默认将数据写入项目的 `output/`，该目录已被 Git 忽略。OCR 在界面中单独初始化，不包含在基础依赖安装中。

运行测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

当前 39 项 Python 测试包括真实二进制 DOC 的中文、表格和图片保留检查。该检查需要固定版本的 office_oxide。

构建 Windows 轻量版：

```powershell
py -3.12 -m pip install -r requirements.txt
.\desktop\download_office_oxide.ps1
.\desktop\build_v1.ps1 -SkipLibreOffice
```

构建机还需 Windows 自带的 .NET Framework C# 编译器。默认通过 `py -3.12` 定位基础 Python 运行环境；需要指定已准备好的 Python 3.12 目录时，使用 `-PythonRuntime`。使用 `-OutputDirectory` 可指定独立输出目录，避免与正在运行的程序共用目录。

构建会校验 office_oxide Windows wheel 的固定 SHA-256，默认成品位于 `release/`。wheel、私有运行时、构建缓存及发布成品不提交到 Git 源码仓库。

| 目录 | 内容 |
| --- | --- |
| `bridge/` | 本机服务、材料处理和 NotebookLM 桥接 |
| `web/` | 工作台、案件与审计界面 |
| `desktop/` | Windows 启动器、安装器和构建脚本 |
| `tests/` | 回归测试与合成 DOC，不含客户数据 |
| `docs/` | 架构记录与发布说明 |
| `research/` | 历史调研；实现状态以当前源码与发布说明为准 |
